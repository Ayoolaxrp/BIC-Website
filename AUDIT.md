## 3. Data layer & roles (Supabase)

`schema.sql` (v2) creates: `profiles` (role: member/admin), `events`, `articles`,
`resources`, `newsletter_posts`, and submission tables (`member_applications`,
`contact_messages`, `sponsorship_inquiries`, `rsvps`, `subscribers`) — all with
**Row Level Security**:

- Anonymous visitors: insert into form tables, read events/articles/resources/newsletter
- Signed-in members: own profile, own RSVPs, own application status (`/member`)
- Admins: full CRUD on content + read all submissions (`/admin`) — enforced by `is_admin()` in RLS

Yes — **member accounts were added** (`/member`): signup/login, membership status,
RSVP history, member resources. Admin console at `/admin`: events, articles,
resources, newsletter posts, and a submissions viewer with live counts.
